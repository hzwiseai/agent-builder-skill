# 岗位组合模式：装哪些任务，怎么连

新岗位先对号入座，选最接近的模式做起点，再决定是改配置、加任务，还是这套模式
根本不适用。**先问一个问题定方向**：你是要客户**给一个信息**，还是要他**点头**？

- 要信息 → 收口用 `collect_required_fact`
- 要点头 → 收口用 `explicit_opt_in`

这一步判错，后面装的任务和填的配置从一开始就是错的。

模板目录用 `design_list_system_templates` 实时读，`design_recommend_system_templates`
按业务描述给候选。**这一页不复制目录**——模板还在增加，抄下来的清单很快就会
和线上对不上。这里只讲不随模板增减变化的判断。

## 八种模式

### A 讲解 → 明确意愿收口 → 转接

客户要先理解产品或方案才可能转化，转化动作是注册、试用、预约、演示之一。

装：渐进说明技能 + 预约任务 + 主动请求人工交接 + 风险人工交接（有案例库再加案例检索）。
用 `journey_handoffs` 把说明技能的收口状态连到预约任务的收集状态。

岗位层要填：发现问题、方案路径、说明单元（每个 `must_convey` 写客户能复述的
事实）、异议、收口（`conversion_checkpoint.fact_key` **必须**出现在某个单元的
`collect_fact_refs` 里，否则永远收不了口）。

常见错法：把「希望 AI 帮我预约客户」记成「本人同意预约演示」；讲完就邀请但
没记进度，于是永远收不了口；`after_unit_keys` 填了全部单元，结果邀请永远发不出。

### B 讲解 + 无回复续讲 + 电话预约

出站或首见后客户常沉默，需要按档位把剩余说明推完。

关键在 `cadence`：**不配就没有自动跟进**。续讲只交付下一个没讲过的单元，
不提问、不收联系方式；只有实际发送成功才写进度；进入终态后不再创建超时事件。

### C 答疑 → 留资

入站咨询，客户明确要资料、方案、演示、报价或回访时才留联系方式。

装一个留资任务即可，行为由任务政策 + 岗位政策 + 话术召回决定，没有
`skill_configuration`。岗位层要填知识需求、维度、岗位政策（先答后留资、
一种联系方式即可、不虚构「资料已发」）和召回绑定。

常见错法：把普通咨询强行变成收联系方式；没有依据时罗列产品模块；留资成功后
又问一次手机号。

### D 行业留资

留资前有行业特定的分支和资格信息（买还是卖、车型、区县）。**这是行业任务，
不是通用抽象。** 相近行业先评估能不能用「通用留资任务 + 岗位维度」解决，
不要复制一个行业任务改名。

### E 预约挂载

任何岗位需要「收联系方式 + 时间 → 创建预约」时作为附加任务挂上，用
`journey_handoffs` 从主技能的收口状态连到预约收集状态。

预约完成后进入已记录状态（可以驻留答疑），客户再说「好的」不重跑预约，
补充问题也不重复创建。

### F 答疑 + 人工跟进

纯客服，**以解决问题为完成，不强加销售转化**。答不了的建人工跟进任务或转人工。

**不要在这类岗位装渐进说明技能。** 需要顺带介绍产品时，用知识 + 按 `ask_fact`
召回话术就够了。

### G 招聘筛选 + 面试邀约

用招聘筛选技能，把岗位（前厅、后厨…）绑到方案路径和资格事实上，每个核查项
写清楚问题本身和为什么问。

### H 订购

草稿 → 客户确认 → 提交 → 回执。**只有 `confirm` 这个 act 算拍板，
`acknowledge` 不算**——「好的」「嗯」不是下单。

### I 一转漏斗

低价体验课或直播把人送进转化场，**AI 不成交**。和模式 A 同一行业技能、同一
知识模板，但**另建一个岗位**。

岗位政策必备：不谈价、不催、不追转化率；付款只认人工核验回执（客户说已付款
只记录原话、交人工，不判到账）；场次时间只按知识给，不让客户选；讲清价值后
才邀请。

**加微承接是主动开场**，不是入站接待：第一句话由我们说，客户还没开口。开场
话术写成「看到您加过来了 + 身份 + 一个容易回答的问题」，并且加微来源通常不在
上下文里，**开场不要假设来源**。还要确认 AI 成员的事件投递渠道含个人微信类，
否则开场和续讲会被挂起不发。

## 通用附加件

| 需求 | 加什么 |
| --- | --- |
| 客户主动要人工 | 主动请求人工交接任务 |
| 投诉、风险情绪 | 风险人工交接任务 |
| 案例或方案检索 | 案例检索技能 |
| 首见问候 | `expression.hard_templates` 绑首次接触事件 |
| 缺项超时追问 | 订阅缺项超时事件 + 对应 SOP |
| 无回复续讲 | `cadence`（只有渐进说明技能支持） |

**两个交接任务不是二选一，但装在一起要知道边界**：主动请求交接认
`act == request_human`，风险交接认 `act == complain`。只装风险任务时，客户平静
地说「我要转人工」不会触发交接——写授权事件观察不到，写操作被拒，客户收到的
是一句「没能转接上」。

## 收口方式决定装什么

| 收口 | 典型场景 | 模式 | 挂什么 |
| --- | --- | --- | --- |
| `explicit_opt_in` | 注册、试用这类客户自己去做的动作 | A | 通常不装写任务；要演示就挂 E |
| `collect_required_fact` | 要到店时间、联系方式、资格信息 | A + E | 收到之后连到预约任务，或留资任务 |
| 直接入口 | 有真实商品和订单能力 | H | 没有订单能力就只讲解 + 给入口，别装订购任务 |

强合规行业（医美、保险、法律、医疗）多一层：线上不诊断、不设计方案、不释法、
不收证据这类「禁止问」级别的规则，要**同时**落到岗位政策的禁止声明引用和知识
模板的答复红线，两边只写一边必然漂移。

## 改配置、加任务，还是根本不该在这一层改

| 情况 | 做法 |
| --- | --- |
| 换行业、换产品、换话术、换异议 | 改岗位的 `skill_configuration`、政策、话术，**不动任务包** |
| 需要多一个转化动作 | 多装一个任务，多一条 `journey_handoffs` |
| 现有任务的状态机或能力绑定不够用 | 这是平台改动，见[平台模板边界](platform-templates.md) |

组织会话改不了任务包的 `control_contract.policies`——它不在可编辑面上。任务的
行为需要变，只能在岗位层用政策覆盖，或者请平台侧改任务包。**覆盖口径要写明
「本条覆盖任务包中关于 X 的表述」**，否则两条并列的指令谁生效取决于模型。
