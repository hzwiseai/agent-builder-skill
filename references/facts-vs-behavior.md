# 资产中的事实与行为

这是知识中心到 AI 团队、销售和客服资产闭环的基础分类。

## 一句话区分

- **事实**回答“世界是什么样”：价格、地址、资格条件、产品参数、营业时间、注册网址、客户已经提供的姓名电话等可核验内容。
- **行为**回答“AI 应该怎么做”：何时询问、询问什么、是否允许调用能力、如何路由、哪些条件阻断、如何回复、何时转人工、完成后进入哪个状态。

事实变化通常来自知识、工具或客户；行为变化必须通过已发布资产声明。模型可以理解事实并在行为边界内做语义选择，但不能把事实变化当成行为变化，也不能凭行为规则创造事实。

## V2 对应位置

| 内容 | 首选承载 | 例子 |
| --- | --- | --- |
| 可复用业务事实 | 知识中心条目、FAQ/RAG 或 live lookup | 薪资、套餐价格、门店地址、注册网址 |
| 跨轮持久客户事实 | `fact_contract` + `record_schema` | 客户选定岗位、手机号、预约时间 |
| 回复约束与业务政策 | `business_policy`、SOP、reply item | 不承诺收入、只用已确认地址 |
| 对话阶段和收集顺序 | `task_asset_package` 的 journey、required facts | 先确认岗位，再收集资料 |
| 能力调用边界 | `capability_contract` 的参数、guard、授权、结果码 | 满足确认条件后才能创建预约 |
| 业务组合和岗位差异 | `business_asset_package`、任务安装配置 | 前厅/后厨方案、产品方案顺序 |
| 实际工具/知识绑定 | Agent 实例资源绑定 | 绑定哪套 FAQ、哪个 MCP server/tool |

## 四个判断问题

1. 去掉这条内容，客户看到的现实信息会不会变？会变，优先按事实处理。
2. 这条内容是否规定 AI 何时提问、拒绝、调用工具或转人工？是，属于行为资产。
3. 这条内容是否需要跨轮保存并被后续能力读取？是，必须有 Fact 契约，不能只写在知识或话术里。
4. 这条内容是否只是这一次工具返回的结果？是，按能力结果和回执处理，不要复制成永久知识。

## 常见混淆

- “周一至周五 10:00–17:00 可预约”同时包含事实和行为：时间窗口是业务事实，“超出窗口时阻断并请客户重选”是行为。两者应分别有知识依据和任务/能力 Guard。
- “满一个月可申请社保”是事实；“客户问社保时主动回答，不要要求先完成资格筛选”是行为。
- “客户选择后厨”是客户 Fact；“岗位未选定前不得进入住宿筛选”是行为。
- 回复正文里的薪资数字是事实投影，不是事实源；来源应回到知识/政策，正文只负责表达。

## 变更顺序

1. 先定位事实源和行为承载字段，不能只搜到一段相似文字就修改。
2. 事实变化：修改知识并发布；有 `asset_ref` 时再编译资产。
3. 行为变化：修改任务/业务包/能力/SOP，补 Eval 并发布；不反向改知识。
4. 两者同时变化：先确认事实，再声明行为如何使用它，最后做发布闭环验证。
5. 资产改动发现新事实：生成带来源版本和字段路径的知识回填提案，人工审核后再发布，不自动把资产文档覆盖回知识中心。

## 验收标准

一次变更完成后，应能回答：事实来自哪个知识/工具/客户 Fact，行为由哪个资产字段声明，运行时使用哪个已发布版本，相关 Eval 是否覆盖了“事实正确”和“行为正确”两件事。
